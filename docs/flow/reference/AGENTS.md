# FLOW reference

## Purpose

Help readers find current interfaces, support, compatibility, and exact portable requirements.

## Ownership

- `index.md` maps reader tasks to references and normative specifications.
- `support.md` separates SDK availability, component runtimes, and qualified host support.
- `sdk.md` and `markdown.md` provide concise author-facing lookup pages.
- `skill-compatibility.md` records current format and execution differences.
- `glossary.md` defines vocabulary and links to its owner.

## Local Contracts

These pages explain current behavior. `../spec/` owns normative requirements.
Keep language SDK availability separate from a host's supported implementations.
Keep experiment findings in `../evidence/`, with their scope and uncertainty intact.

## Work Guidance

Lead each entry with the reader's decision or lookup task.
Use tables for exact mappings and links for complete requirements.
Label examples explicitly. Keep support claims tied to qualified implementations.

## Verification

Run the documentation checker and a fresh FLOW site build.
Check reference links, Markdown publication, and exact machine-resource destinations.
